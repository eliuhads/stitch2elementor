## 🎯 What is stitch2elementor?

stitch2elementor is an open-source AI agent skill for tools like [Antigravity](https://antigravity.dev), Cline, or any MCP-compatible agent. It orchestrates a fully automated pipeline that:

1. Takes UI designs generated by **Google Stitch**
2. Extracts their **HTML + Tailwind** output
3. Compiles them into native **Elementor Flexbox JSON V4**
4. Injects everything into **WordPress** via a hybrid FTP + PHP pipeline

**No Figmentor. No UiChemy. No premium plugins. No manual recreation. Zero cost.**

## ⚡ Quick Start

### Prerequisites
- An MCP-compatible AI agent (Antigravity, Cline, etc.)
- WordPress site with Elementor 3.6+ installed
- FTP access to the WordPress server
- Google Stitch account

### Installation

1. **Clone or download** this skill into your agent's skills directory:
```bash
git clone https://github.com/eliuhads/stitch2elementor.git
```

2. **Configure MCP servers** in your agent:
   - `stitch` — Google Stitch screen management
   - `wp-elementor-mcp` — WordPress page/post CRUD
   - `elementor-mcp` — Direct Elementor manipulation
   - `novamira-mcp` — *(optional)* PHP sandbox + deep builder access

3. **Set up credentials** in `.env`:
```env
FTP_HOST=your-server.com
FTP_USER=your-ftp-user
FTP_PASS=your-ftp-password
WP_URL=https://your-site.com
WP_USER=admin
WP_APP_PASSWORD=xxxx-xxxx-xxxx-xxxx
```

4. **Start building** — just type `go!` in your agent chat!

## 🧠 Battle-Tested Protocols

> These rules were born from real production deployments. They are **non-negotiable**.

### ⚠️ The ID-Shifting Problem
Every time `sync_and_inject.js` runs, WordPress assigns **brand new IDs**. Any `wp_id` you recorded before is immediately obsolete.

**Solution**: Always run the "AHORA SI" protocol after injection:
1. Capture new Homepage ID from injection output
2. Update `page_manifest.json` with all new IDs
3. Run `flush_cache.php` with the new Homepage ID
4. Run `fix_material_symbols.js`
5. Run `fix_slugs.js`
6. Update `memoria_estado.md`
7. Verify visually

### 💉 Hybrid FTP + PHP Injection
ModSecurity/WAF blocks large JSON payloads via REST API (HTTP 406/401). The hybrid injection bypasses HTTP entirely:
- Upload JSON via FTP
- Execute PHP server-side for direct DB writes
- Auto-cleanup of temporary PHP files

### 📱 Responsive Mapping
Tailwind uses **Mobile-First** (`flex-col sm:flex-row`), Elementor uses **Desktop-First**. The compiler transposes mathematically:
- Tailwind `base` → Elementor mobile breakpoint
- Tailwind `sm:` → Elementor tablet breakpoint
- Tailwind `md:` → Elementor desktop breakpoint

## 🙋 FAQ

**Q: Does this work with Elementor Free or only Pro?**
A: Core JSON injection works with Elementor Free. Flexbox Containers require Elementor 3.6+. The nav-menu widget used in auto-generated headers requires Elementor Pro.

**Q: What is this "ID-Shifting" problem?**
A: Every time you re-inject pages, WordPress creates new post IDs. Your previously noted IDs are immediately stale. Always run `flush_cache.php` with the new Homepage ID after any injection.

**Q: I get 406 Not Acceptable or 401 Unauthorized on the WP REST API.**
A: Expected behavior. ModSecurity/WAF blocks large JSON payloads. The pipeline uses Hybrid FTP + PHP Injection by default to bypass the HTTP firewall entirely.

**Q: My homepage is broken after injection.**
A: Run `node scripts/maintenance_only.js [new_homepage_id]`. This is the Config-Only mode — it sets WordPress's `page_on_front`, regenerates Elementor CSS, and cleans up automatically.

**Q: How do I use Novamira MCP?**
A: Install the [Novamira plugin](https://novamira.com) on your WordPress site, configure the `novamira-mcp` server in your agent, and use `mcp-adapter-execute-ability` for PHP sandbox execution. See the Novamira Integration section above.
